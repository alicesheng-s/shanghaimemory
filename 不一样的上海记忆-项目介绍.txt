不一样的上海记忆
AI 时代城市工业文化遗产的现场讲述与路线策展

参赛方向：工业文化创新发展大赛 · 2026 人工智能未来设计赛 · OPC 创新创业方向（AI+软件赛道）
版本：0.6.1
形态：Android 原生应用（minSdk 26，targetSdk 36）


一、一句话

把手机举到一栋老厂房、一座水厂、一个仓库门口，它会先联网查公开资料，再讲出这栋建筑自己的来历；想串成一条线，就自己挑点，让它排成一条能走完的路线。


二、要解决的问题

上海的工业遗产密集，但现场几乎读不出来。杨树浦路沿线从自来水厂到发电厂，是远东最早的市政工业带，可今天走在路上，看到的只是一排旧房子。现有的导览产品有两个断层：

一是内容断层。百科条目讲的是机构职能、建筑参数、行政级别，不告诉你这栋楼当年生产什么、为什么建在这里、后来怎么停下。
二是场景断层。攻略给的是"必去榜单"，不是"你此刻站在哪里"。人已经站在楼下，却没有入口。

这两件事 AI 都能做，但直接让大模型讲会出两种事故：把便利店当成历史建筑讲，或者把企业工商注册信息当成城市记忆讲。所以本项目把"能不能讲"和"怎么讲"分开处理。


三、核心功能

1. 地图漫游（现场讲述）

地图中心固定一个游标，手指平移地图，停稳一秒后自动辨认游标所在的位置：周边 POI 检索加逆地理编码，按"文化价值优先"排序给出候选。用户可以从候选列表里换一个地点。点"了解更多"进入对话，先检索公开资料，再流式生成四段内容：

  地点介绍  这栋楼或这条街是什么
  经典历史事件  一到两件带年份与人物的事
  近期新闻  近一两年确实发生过的
  近期活动  当前在办或临近的展览与开放信息

生成是流式的，首字通常在三秒内出现；没有的内容写"暂无可靠近况"，绝不编。


2. 地标闸门（本项目的核心判断）

不是每个地点都值得讲。系统内置一套可配置的筛选规则，从名称词表、高德分类、名称长度、楼盘与门店特征四个维度判断，命中即拒绝，并在卡片上写清理由（例如"某某是日常消费或办事场所，没有公共历史可讲"）。用户可在设置里调整四项：

  医院学校机关是否算可讲述地点（默认算）
  公司门店写字楼是否算（默认不算）
  严格模式：只认名字里带旧址、故居、厂房、码头、海关这类词的地点
  自定义关键词：写"洋行、纱厂"这类词，命中即放行

被拒时模型也不会硬编。提示词里有明确的拒答格式与三条写作底线：只讲这栋建筑的来历与变迁，禁止罗列机构职能与科室，连一个确切年份都给不出就直接说没有。这一层是本项目与"套壳大模型"最本质的差别。


3. 游览路线（三层选点）

点"游览路线"后先进菜单，分两条路：

  预设路线  电力之旅与工业之旅两条主题线，各 8 个点，全部有真实门牌与史料出处。电力之旅从 1882 年的电灯讲到 1913 年的烟囱：杨树浦电厂遗迹公园（105 米烟囱）、杨树浦水厂（1883 年通水）、上海当代艺术博物馆（1897 年南市发电厂）、世界技能博物馆（1921 年永安栈房）等。工业之旅走船坞、纱厂、盐仓、糖厂、宰牲场与邮局。

  自定义路线  用户写关键词与内容偏好（近期活动／历史建筑／都行），关键词支持 and、or、not 与括号。两项交给模型联网检索，返回候选地点，再定位算距离。

选点页是两列网格，每个点显示简介与距当前定位的真实距离，右上角加号加入行程。选完才进对话，问三件事（能走多久、必须看或不想看什么、同行是谁），然后生成路线。

选点与生成之所以分开，是因为模型找的点可能不存在，必须等地理编码能定位之后才让用户看见；顺序与停留时长交给模型，去哪些点由用户决定。用户挑定的站点是硬约束，模型只许排序，不许增删。


4. 路线实时向导

生成后回到地图，自动画出站点标记与连线，按定位提示当前该去哪一站，显示直线距离，进入 80 米范围提醒到站并轻振，可逐站推进。


5. 模型服务（自带 Key）

Key 只存在本机，不上传。内置 DeepSeek、智谱、Kimi 三家预设与自定义端点，支持一键拉取可用模型列表、连通性测试（报首字延迟与总耗时）、联网检索开关、自定义检索端点。

关键工程决策：主流模型默认开启思考模式，会直接击穿"首字三秒"的体验指标。本项目在请求层显式关闭思考（thinking.type=disabled 或 reasoning_effort=low），失败时自动去参重试。这一条不写进代码就会被当成"AI 很慢"。


6. 外观与阅读体验

四套色板（墨金、樱花粉、青瓷、自定义）各配明暗两版，可跟随系统。自定义模式下用户挑一个主色，其余十个色值由程序按色相与明度派生，对比度由程序兜底，不要求用户懂设计。另有圆角、背景不透明度、五种正文字体（含随包的 JetBrains Maple Mono）、五档字号可调。

正文渲染器对模型输出做容错：标题、有序列表编号、引用、高亮、行内代码、分隔线都转成带颜色的样式，同时剥掉模型误用的 Markdown 记号。

系统语音朗读可开关、可调语速，设置页带试听与引擎状态诊断（能显示当前用的是哪个引擎、中文语音包缺失时给出明确提示）。


四、技术实现

语言与框架：Kotlin，Android 原生 XML View，单 Module 分层（data / ui / ui.theme / ui.render）。
地图与检索：高德 3D 地图、搜索、定位三合一 SDK（V11.3.100 / 11.3.101 / 9.8.1），已验证 16 KB page size 对齐，适配 Android 15 及以上的新内存页要求。
检索与生成两段式：先用搜索接口取结构化资料（支持 site:、after: 等运算符），再把资料作为写作依据交给模型。按话题切换检索来源：游戏二次元偏 B 站、贴吧、小黑盒；美食景色偏小红书、大众点评、微博；冷门话题偏 B 站、优酷、贴吧、NGA；历史建筑不限站，因为地方志、公众号与新闻站分散在各处。
提示词工程：四套提示词（现场讲述、追问、路线、候选地点）全部约束为纯文本分段结构，禁用 Markdown 记号，并对字数上限做了硬要求，避免截断导致解析失败。
容错：路线 JSON 解析有三道防线，先 JSON 模式，再退普通模式，最后按括号配对抢救已写完整的站点。
配置：DataStore 本地存储，无账号、无云端。


五、与同类产品的差别

不是文旅攻略 App。攻略给榜单，本项目给"你脚下这一处"。
不是通用聊天机器人套壳。地标闸门决定哪些地方能讲，写作底线决定讲什么，两者都在客户端与提示词里双重约束。
不是博物馆数字导览。不依赖预建内容库，用户可以走到任何一个真实存在的老建筑前，现场生成，同时又有 16 个离线策展点保底，无网络时也能读。


六、当前完成度

截至 0.6.1，全部功能已在真机（Redmi K80，Android 16，澎湃 OS 3）跑通完整链路：定位与辨认、四段生成、候选切换、闸门拒答与原因回显、两条预设线的选点与生成、自定义关键词检索（实测 power plant 返回 10 处电厂旧址，waterfront 返回 10 处滨江仓库）、单站点生成、路线画线与到站提醒、主题切换与字体导入、语音朗读。

已知边界：极冷门的地点（例如"民生码头八万吨筒仓"）地理编码可能落到同名另一处，距离显示会偏；此时以对话内的站名为准，不影响路线本身。


七、运行要求

Android 8.0 及以上。需要用户自备一个大模型 API Key（DeepSeek、智谱、Kimi 或任何兼容 OpenAI 接口的自定义端点），在设置里填入即可。高德地图 Key 已内置。


八、数据与合规

所有内容标注来源性质：联网检索生成的结尾统一标注"内容由 AI 联网检索生成，仅供参考"；未联网时标注"未联网核实"；有争议的史实写明"此事待考"；无法给出的段落直接写"暂无可靠信息"，不做填充。
API Key 仅存本机，应用不申请任何账号体系，不上传用户位置与对话内容。
