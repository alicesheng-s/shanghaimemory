不一样的上海记忆
AI 时代城市工业文化遗产的现场讲述与路线策展

参赛方向：工业文化创新发展大赛 · 2026 人工智能未来设计赛 · OPC 创新创业方向（AI+软件赛道）
版本：0.7.0（源码审查与文本优化版）
形态：Android 原生应用（minSdk 26，targetSdk 36）


一、一句话

把手机举到一栋老厂房、一座水厂、一个仓库门口，它会先联网检索公开资料，再讲出这栋建筑自己的来历；想串成一条线，就自己挑点，让它排成一条走得完的路线。


二、要解决的问题

上海的工业遗产密集，但现场几乎读不出来。杨树浦路沿线从自来水厂到发电厂，是远东最早的市政工业带，可今天走在路上，看到的只是一排旧房子。现有的导览产品有两个断层：

一是内容断层。百科条目讲的是机构职能、建筑参数、行政级别，不告诉你这栋楼当年生产什么、为什么建在这里、后来怎么停下。
二是场景断层。攻略给的是「必去榜单」，不是「你此刻站在哪里」。人已经站在楼下，却没有入口。

这两件事 AI 都能做，但直接让大模型讲会出两种事故：把便利店当成历史建筑讲，或者把企业工商注册信息当成城市记忆讲。所以本项目把「能不能讲」和「怎么讲」分开处理。


三、核心功能

1. 地图漫游（现场讲述）

地图中心固定一个游标，手指平移地图，停稳片刻后自动辨认游标所在的位置：周边 POI 检索加逆地理编码，按「文化价值优先」排序给出候选。用户可以从候选列表里换一个地点，也可直接按地名搜索直达目标。点击「了解更多」进入对话，先检索公开资料，再流式生成四段内容：

  地点介绍      这栋楼或这条街的来历与变迁
  经典历史事件  一到两件带年份与人物的事
  近期新闻      近一两年确实发生过的公开报道
  近期活动      当前在办或临近的展览与开放信息

生成是流式的，首字通常在三秒内出现；没有的内容写「暂无可靠近况」，绝不编造。


2. 地标闸门（本项目的核心判断）

不是每个地点都值得讲。系统内置一套可配置的筛选规则，从名称词表、高德分类、名称长度、楼盘与门店特征四个维度判断，命中即拒绝，并在卡片上写清理由（例如「某某是日常消费或办事场所，没有公共历史可讲」）。用户可在设置里调整四项：

  医院、学校、机关也算（默认开启）
  公司门店、写字楼也算（默认关闭）
  严格模式：只认历史建筑（默认关闭）
  自定义关键词：填写「洋行、纱厂」等词，命中即放行

被拒时模型也不会硬编。提示词里有明确的拒答格式与三条写作底线：只讲这栋建筑的来历与变迁，禁止罗列机构职能与科室，连一个确切年份都给不出就直接说没有。这一层是本项目与「套壳大模型」最本质的差别。


3. 游览路线（三层选点）

点击「游览路线」后先进入菜单，分两条路：

  预设路线  电力之旅与工业之旅两条主题线，各 8 个精选点位，全部有真实门牌与史料出处。电力之旅从 1882 年外滩的第一盏电灯讲到 1913 年的远东第一火力发电厂：杨树浦电厂遗迹公园（105 米烟囱）、杨树浦水厂（1883 年 8 月 1 日通水）、上海当代艺术博物馆（南市发电厂旧址，源起 1897 年华商自办南市电灯厂）、世界技能博物馆（1921 年永安栈房）等。工业之旅串联船坞、纱厂、筒仓、糖厂、宰牲场与邮局。
  自定义路线  用户输入关键词与内容偏好（近期活动 / 历史建筑 / 都行），关键词支持 and、or、not 与括号组合。两项交由模型联网检索返回候选地点，再通过高德地理编码补齐坐标并计算距当前位置的真实距离。

选点页采用两列网格，每个点位显示简介与实时距离，右上角「+」加入行程。选完后进入对话，回答三个问题（能走多久、必须看或不想看什么、同行是谁），再由模型生成路线。

选点与生成之所以分开，是因为模型推荐的地点必须经真实地理编码验证；去哪些点由用户做硬约束，模型只负责排序与停留时长，不擅自增删。


4. 路线实时向导

生成后回到地图，自动绘制站点标记与连线，按实时定位提示下一站名称与直线距离，进入 80 米范围自动提醒到站并轻振，逐站推进直至全程完成。


5. 新手指引与模型服务（自带 Key）

首次打开自动拉起 5 页新手指引（产品理念 → 填写 Key → 挑选配色与明暗 → 地图用法 → 路线用法），之后随时可在设置一级菜单中重看。

API Key 仅保存在本机 DataStore，不上传云端。内置 DeepSeek、智谱 GLM、Kimi 三家预设与自定义 OpenAI 兼容端点，支持一键拉取可用模型列表、连通性测试（汇报首字延迟与总耗时）、联网检索开关与自定义检索端点。

关键工程决策：主流模型默认开启思考模式，会直接击穿「首字三秒」的体验指标。本项目在请求层显式关闭思考（thinking.type=disabled 或 reasoning_effort=low），遇兼容端点不支持时自动去参重试。


6. 外观与阅读体验

四套色板（墨金、樱花粉、青瓷、自定义）各配明暗两版并支持跟随系统。自定义模式下用户只需挑选一个主色，其余十个令牌色值由程序按 HSL 关系自动派生，对比度由代码兜底。另有圆角、背景不透明度、五种正文字体（含随包的 JetBrains Maple Mono 与本地字体导入）、字号缩放可调。

正文渲染器对模型输出做容错：标题、有序列表编号、引用、高亮、行内代码、分隔线均转为着色样式，同时剥离模型误输出的 Markdown 记号。

系统语音朗读支持开关、语速调节、试听与引擎状态诊断（显示已安装引擎，缺少中文语音包时给出明确引导）。


四、技术实现

语言与框架：Kotlin，Android 原生 XML View + ViewBinding，单 Module 分层（data / data.llm / data.model / ui / ui.theme / ui.render）。
地图与检索：高德 3D 地图、搜索、定位三合一 SDK（V11.3.100 / 11.3.101 / 9.8.1），已验证 16 KB page size 对齐，适配 Android 15 及以上内存页要求。
检索与生成两段式：先用搜索接口取结构化资料（支持 site:、after: 等运算符），再把资料作为写作依据交给模型。按话题切换检索来源：游戏二次元偏 B 站、贴吧、小黑盒；美食景色偏小红书、大众点评、微博；冷门话题偏 B 站、优酷、贴吧、NGA；历史建筑不限站，确保地方志、公众号与新闻站均可命中。
提示词工程：四套提示词（现场讲述、追问、路线、候选地点）全部约束为纯文本分段结构，禁用 Markdown 记号，并对字段字数上限做了硬约束，防止截断导致 JSON 解析失败。
容错机制：路线与选点 JSON 解析设三道防线——JSON 模式、普通模式重试、按括号配对抢救已闭合条目。
本地配置：DataStore 本地存储，无账号、无云端同步。


五、与同类产品的差别

不是文旅攻略 App。攻略给榜单，本项目给「你脚下这一处」。
不是通用聊天机器人套壳。地标闸门决定哪些地方能讲，写作底线决定讲什么，客户端与提示词双重约束。
不是封闭式博物馆导览。不依赖预建内容库，用户走到任意真实老建筑前皆可现场生成，同时内置 10 篇离线策展故事与 16 个精选点位兜底。


六、当前完成度

截至 0.7.0，全部核心链路已在真机（Redmi K80，Android 16，澎湃 OS 3）完整跑通：首次 5 页新手指引、冷启动定位与地点辨认、四段流式生成、附近候选切换、地标闸门拒答与原因回显、两条预设线选点与生成、自定义布尔关键词检索、单站点生成、路线画线与逐站到站提醒、主题与透明度切换、本地字体导入及系统语音朗读。

已知边界：极冷门地点（如「民生码头八万吨筒仓」）地理编码偶发偏移至同名处，卡片距离仅供参考，进对话后模型按站名正常排程。


七、运行要求

Android 8.0（API 26）及以上。用户需自备一个大模型 API Key（DeepSeek、智谱 GLM、Kimi 或任意兼容 OpenAI 协议的端点），在引导页或设置页填入即可；高德地图 Key 通过 local.properties 在构建时注入。


八、数据与合规

所有内容均标注来源性质：联网检索生成的结尾统一标注「内容由 AI 联网检索生成，仅供参考。」；未联网时标注「内容由 AI 生成，未联网核实，仅供参考。」；有争议的史实写明「此事待考」；缺失信息直接写「暂无可靠近况 / 暂无可靠活动信息」，不做填充。
API Key 仅存本机，应用不设立账号体系，不上传用户位置与对话内容。
