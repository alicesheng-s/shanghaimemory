# 不一样的上海记忆

一个把「城市阅读」变成「边走边听故事」的 Android 应用。在地图上停下，附近的工业遗产、老厂房、水厂、仓库就会开口讲自己的来历——有据可查的部分讲证据，查不到的部分明确标「此事待考」。

面向工业文化创新发展大赛 · 2026 人工智能未来设计赛（OPC 创新创业方向，AI+软件赛道）。当前版本 1.3.0。

## 环境要求

| 组件 | 版本 | 配置位置 |
| --- | --- | --- |
| JDK | 21（Temurin 21） | 环境变量 `JAVA_HOME` |
| Android SDK | Platform 36 / Build-Tools 36.0.0 | `local.properties` 的 `sdk.dir` |
| Gradle | 8.14.3 | 工程自带 `gradlew` / `gradlew.bat` |
| AGP / Kotlin | 8.13.2 / 2.2.20 | 由 wrapper 自动拉取 |

工程自带 Gradle Wrapper，换机器只需改 `local.properties` 里的 `sdk.dir` 与 `AMAP_KEY`。

## 构建

```powershell
# 换成你自己的 JDK 与 Android SDK 路径
$env:JAVA_HOME='C:\path\to\jdk-21'
$env:ANDROID_HOME='C:\path\to\android-sdk'
.\gradlew.bat assembleDebug
```

产物：`app\build\outputs\apk\debug\app-debug.apk`（约 78 MB，含 arm64-v8a 与 armeabi-v7a 两套高德 so；只留 arm64 可压到约 47 MB，改 `app/build.gradle.kts` 的 `abiFilters`）。

安装到设备：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## 两把 Key

**高德地图 Key（必需，决定地图能不能出图）**

1. 打开 https://console.amap.com/dev/key/app ，用高德开放平台账号建应用。
2. 添加 Key：服务平台选 **Android 平台**，Package Name 填 `com.shanghai.memory`，SHA1 填你本机签名证书的指纹（`keytool -list -v -keystore %USERPROFILE%\.android\debug.keystore -alias androiddebugkey -storepass android` 可查）。
3. 拿到 32 位 Key 后写进 `local.properties`：

```
AMAP_KEY=你的32位Key
```

4. 重新 `assembleDebug`。Key 通过 `manifestPlaceholders` 注入到 `<meta-data com.amap.api.v2.apikey>`，代码里不硬编码。

**大模型 Key（必需，决定故事能不能生成）**

App 内「设置」页填写，只写入本机 DataStore，不上传、不打日志。支持四类服务商：

| 预设 | 默认模型 | 联网检索 |
| --- | --- | --- |
| DeepSeek | `deepseek-flash` | 官方 Search API |
| 智谱 GLM | `glm-4-flash` | 官方 Web Search API |
| Kimi / Moonshot | `moonshot-v1-32k` | 无，纯对话降级 |
| 自定义 | 自填 | 可选自定义检索端点 |

「测试连接」会真实发一次请求，并显示 **首字延迟 / 总耗时**，直接对应「首字 ≤ 3s」这条指标。

## 功能对照

| 需求 | 实现位置 | 说明 |
| --- | --- | --- |
| F1 地图漫游 | `ui/MapActivity.kt` + `data/AmapService.kt` | 固定中心游标贴图，拖动地图 400 ms 去抖后检索周边 POI，取最近一处并逆地理编码补区名地址 |
| F1 地标准入 | `data/LandmarkGate.kt` + `data/GatePolicy.kt` | 门店、地铁公交、纯住宅这类噪音 POI 在进故事之前就被挡掉，并给出挡掉的理由，避免拿一个便利店硬讲历史 |
| F1 故事流式生成 | `ui/ChatActivity.kt`（地点讲述通道）+ `data/StoryRepository.kt` | 检索 → 生成两段式，逐字上屏，资料出处单列；输出落在常驻会话里，退出界面不丢 |
| F2 游览路线 | `ui/RouteActivity.kt` → `ui/ChatActivity.kt`（行程策划通道）→ `ui/MapActivity.kt` | 选预设或写主题进对话，AI 先告知联网状态、再问备注，据此重排路线；方案回到地图画线，定位跟着走，走进 80 m 提示到达 |
| F3 BYOK | `ui/SettingsActivity.kt` + `data/SettingsStore.kt` + `data/llm/ModelCatalog.kt` | Key 存 DataStore；可测连通性；可一键拉取该 Key 下可用模型 |
| F4 合规标注 | `data/PromptTemplates.kt` | 传说标注、争议处「此事待考」、结尾 AI 来源声明；四段输出（地点介绍 / 经典历史事件 / 近期新闻 / 近期活动） |

无 Key 或断网时不会白屏：`data/CuratedStories.kt` 内置 10 条人工策展点位故事，`data/CuratedRoutes.kt` 内置 2 条路线，作为演示兜底。

## 已知取舍

- **提示词合并**：需求文档里 P1（联网型）与 P1'（纯对话型）原本是两条路。实现改为统一走「App 侧检索 + P1' 结构」，因为检索真正发生在客户端，模型不需要自带联网能力；有检索时尾注为「内容由 AI 联网检索生成，仅供参考。」，无检索时降级为「内容由 AI 生成，未联网核实，仅供参考。」
- **首字延迟**：DeepSeek 默认开启思考模式（强度 high），会直接击穿 3 秒指标。`ChatClient` 每次请求都显式注入 `thinking:{"type":"disabled"}`；若服务端拒绝该参数（HTTP 400/422），自动去掉参数重试一次。智谱侧改用 `reasoning_effort:"low"`。
- **16 KB page size**：演示机 Redmi K80 跑 Android 16，要求 so 按 16 KB 对齐。已实测三支 arm64 so 的 `PT_LOAD p_align` 均为 `0x4000`，`zipalign -c -P 16` 通过，符合要求。
- **未做**：账号体系、UGC、AR、iOS、上海以外城市。

配套的容错渲染：`ui/render/MarkdownLite.kt` 会吃掉模型偶尔返回的 `**`、`##`、`-`、`` ` ``、表格分隔行，把 `【标题】` 放大加粗，避免出现「原样一坨符号」。

已知取舍：

- **会话只在进程内存**：`ChatStore` 是内存对象，杀进程即清空。要跨启动保留得换 Room 或落盘 JSON，本期未做，侧栏底部已向用户写明。

## 0.3.1 版

**辨认出的地点与地图对不上（偶发）**

三个原因叠在一起：

| 原因 | 说明 | 改法 |
| --- | --- | --- |
| 只在高德 POI 里挑最近的一个 | 搜索半径 900 米，游标停在一栋老楼前，返回的常是五百米外的商场；分类里还漏了「地名地址 / 交通设施」，老楼本身根本没被搜到 | 逆地理负责认「中心点本身是哪里」，POI 只在 120 米内才算「脚下就是它」；搜索改为 120 → 400 → 900 米分级，脚下有就不放宽 |
| `runCatching` 吞掉协程取消 | 被取消的旧请求会继续往下跑，把上一个位置的结果写回界面；快速拖动后显示的就是旧位置 | 取消异常显式重抛；另加请求序号 `requestSeq`，落地前对不上直接丢弃 |
| 名称与地址来源不同 | 名字取自最近 POI、地址取自中心点逆地理，两处不一致时读起来更乱 | 名称与地址一律来自同一次判定结果；距离不再写进第二行，改为状态行说清「游标附近的地标：X · 约 N 米」 |

用户可感知的变化：游标停在哪栋楼前，卡片就报那栋楼；若附近确实没有可命名的地点，卡片给「路名 + 门牌」，状态行注明最近地标与距离，不再假装是脚下。

**行程策划报「模型返回的路线格式无法解析」**

根因不是格式，是长度：`maxTokens = 1600` 对 4–6 站、每站三个中文字段的 JSON 来说正卡在边缘，模型写到第六站就被截断，右括号缺失，`JSONObject` 必然抛异常。所以是"有时"失败。

三道防线：

1. 上限提到 3000，提示词改成单行紧凑的 JSON 样例，并写明 `reason ≤ 30 字`、`story_hook ≤ 24 字`、`transition_logic ≤ 60 字`。
2. 解析器加抢救：正常解析失败时，按括号配对把 `stops` 里**已经写完整**的站点逐个捞出来（字符串转义、未闭合对象都能正确跳过），再用正则取 `route_name` / `theme`，凑成一条可用路线，不再整条作废。
3. 仍然读不出来，就换非 JSON 模式再要一次（同提示词 + 「第一个字符是 {，最后一个字符是 }」）。两次都失败才报错，并且把收到的字数和开头片段带进错误信息，方便判断是截断、拒答还是模型换了输出格式。

## 0.5.0 版

### 亮色模式

三套色板（墨金 / 樱花粉 / 青瓷）各自都有暗版与亮版，`Theme.ShanghaiMemory.*.Light` 继承 `Theme.Material3.Light.NoActionBar`，`android:windowLightStatusBar` 置 true，状态栏图标跟着变深。设置里三选一：跟随系统 / 亮色 / 暗色，默认跟随系统。

### 自己配颜色

只让用户挑**一个主色**，其余十个令牌按 HSL 关系派生（`PaletteColors.derive`）：背景取主色相同色相、极低饱和度、明度 0.055（暗版）或 0.968（亮版），卡片、描线、次要文字依次拉开层次，危险色与成功色保留固定色相。这样对比度由代码保证，用户不会配出「白字压浅黄」。圆角单独一个滑块，0–28dp。

实现方式值得记一笔：Android 没有办法在运行时生成 style 资源，所以静态主题只负责给控件一个**初始色**（某套预设色板的色值），真正渲染前由 `ThemeEngine.recolor` 遍历视图树，把每个控件的当前颜色拿去预设反查表里查出它本来想表达的角色，再换成派生色板里的同角色色。布局文件一行没改。

两个坑：
1. `PaletteColors` 的反查表依赖 `PRESETS`，而 `PRESETS` 的元素本身就是 `PaletteColors`，实例初始化阶段展开会无限递归爆栈。改成 `by lazy`。
2. `ImageView` 的 tint 若写在 vector 的 `<vector android:tint>` 上，`imageTintList` 读到 null，反查不到角色。必须在布局的 `ImageButton` 上加 `android:tint`；`layer-list` 画的光标则要靠 `recolorDrawable` 钻进每层 `GradientDrawable` 改色。

### 渲染增强

`MarkdownLite` 从「去标记」升级为「着色 + 多格式」：标题用主色、有序列表编号用主色、引用行加 `▏` 前缀并降为次要文字、`==高亮==` 加底色、行内代码用等宽 + 强调色、`***斜体***`、分隔线转 `· · ·`。模型偶尔漏写标记也能正确分段——四段标题的 `【】` 与 `##` 两种写法都认。

### 字体

五档：系统黑体 / 系统宋体 / 系统等宽 / 随包的 JetBrains Maple Mono / 自己导入的 `.ttf`、`.otf`。导入走 SAF，文件复制进应用私有目录（上限 20MB，防止误选大文件撑爆存储），导入后清字体缓存并立即重建界面。字号 0.85×–1.45×，只作用于打了 `tag="sh:prose"` 的正文控件，标题与按钮不跟着变。

### 源码审查

按「Key 会不会漏、输入会不会崩、边界会不会越」三条线过了一遍：

| 检查点 | 结论 |
| --- | --- |
| API Key 是否进日志 | 全工程无 `Log` / `println` / `printStackTrace`，异常信息里不含 Key |
| Key 是否随备份外流 | `android:allowBackup="false"`，adb backup 与云备份都不会带上 DataStore |
| Key 是否被自动填充服务带走 | `et_apikey` 标 `importantForAutofill="no"` |
| 明文传输 | `usesCleartextTraffic="true"` 保留（要连局域网自建网关），但自定义端点填 `http://` 时设置页会明确警告，回环与私网地址不警告 |
| 用户输入色值 | `Color.parseColor` 全包在 `runCatching` 里，非法输入按格式错误提示，不抛异常 |
| 导入文件 | 20MB 上限 + 复制到私有目录；`Typeface.createFromFile` 包 `runCatching`，坏字体只会回落到默认字体 |
| 正则回溯 | `MarkdownLite` 的匹配都是线性量词，无嵌套重复，不存在 ReDoS |
| 组件导出 | 只有带 LAUNCHER 的 `MapActivity` 是 exported，其余三个 Activity 均 `exported="false"` |
| Intent 参数 | 聊天页的 6 个 extra 仅由本应用自己构造，外部无法唤起 |
| 高德 Key | 只存在于 `local.properties` → manifest placeholder，源码里没有明文 |

遗留项（记下来，不假装没有）：会话只在进程内存里，杀进程即清空；单通道消息数无上限，极长会话会累积内存。

## 0.5.6 版

这一版只修一件事故：**朗读从头到尾没有声音，而且不报错。**

### 真正的根因

不是代码没调用，是 `TextToSpeech` 根本没连上引擎。日志里是这一行：

```
I AppsFilter: interaction: PackageSetting{com.shanghai.memory} -> PackageSetting{com.xiaomi.mibrain.speech} BLOCKED
I TextToSpeech: Sucessfully bound to com.xiaomi.mibrain.speech   ← 加了 queries 之后
```

Android 11 起应用默认只能看见自己声明过的包。`targetSdk` 已经到 36，而清单里从来没声明要查询语音引擎，于是系统把 `com.xiaomi.mibrain.speech` 过滤掉，`TextToSpeech` 初始化直接返回 `ERROR (-1)`。旧代码把这种情况当「还没准备好」，把文本塞进 `pending` 就再也不动，界面上看起来就是「点了没反应、也没有任何提示」。

修法只有两行清单：

```xml
<queries>
    <intent>
        <action android:name="android.intent.action.TTS_SERVICE" />
    </intent>
</queries>
```

### 顺带修掉的四处隐患

| 位置 | 原来的问题 | 现在 |
| --- | --- | --- |
| `TtsSpeaker` 初始化 | 失败就静默 `ready = false`，文本永远卡在 `pending` | 有 `State` 枚举（INIT/READY/NO_ENGINE/LANG_MISSING/FAILED）与 `detail` 人话说明 |
| 语言设置 | `engine.language = SIMPLIFIED_CHINESE` 的返回值从不检查 | 先 `isLanguageAvailable` 再 `setLanguage`，缺中文语音包会明确说「去系统设置下载」 |
| `speak()` | 第三个参数传 `null` Bundle，部分厂商实现会空指针 | 传 `Bundle()`，并检查返回码 `TextToSpeech.ERROR` |
| 多引擎 | 只用系统默认引擎，起不来就彻底没声 | 默认引擎失败且装了 `com.google.android.tts` 时自动回退过去 |

### 界面上的可观测性

- 设置 → 检索与朗读，新增「试听一句」按钮和状态行：能直接看到引擎是可用还是失败、失败原因是什么、播放中按钮会变成「正在朗读…」。
- 状态行还会列出系统里装了哪些语音引擎，方便判断是不是缺引擎。
- 聊天页在朗读不可用时弹一次 Toast 说明原因，不再让人对着没反应的界面猜。
